# 文档维护规则

## 分类

| 目录           | 放置内容                               | 是否作为当前规范           |
| -------------- | -------------------------------------- | -------------------------- |
| `docs/roadmap` | 当前范围、优先级和工程路线             | 是，只有仍有决策价值的条目 |
| `docs/design`  | 当前架构、设计契约和安全边界           | 是                         |
| `docs/rules`   | 长期贡献与维护规则                     | 是                         |
| `docs/archive` | 已被当前实现或新文档取代的资料摘要     | 否，仅供历史追溯           |
| `docs/tmp`     | 有明确时效的计划、交接、实验和验证记录 | 否，过期后删除或归档       |

根目录 `README.md` 是中文用户入口，`docs/README-en.md` 是英文用户与开发者入口。两者只保留面向用户和贡献者的必要信息，项目设计细节链接到本目录的当前文档。

## 稳定文档

- 以源码、配置、workflow 和可复现命令为事实来源；不要把聊天结论或内部飞书文档作为唯一依据。
- 设计文档记录当前边界，不写“迁移中”的大段临时章节。尚未批准的方案只能放在 `docs/tmp`。
- 不维护脱离源码的完整 API 快照。组件类型、后端路由和插件能力发生变化时，只更新稳定的使用约束和源码锚点。
- 链接使用仓库相对路径；移动文件后用 `rg` 搜索旧路径，确保 README、PR 模板和其他文档没有断链。

## 临时文档

`docs/tmp` 只允许存放有明确失效条件的资料，例如阶段计划、交接说明和一次性验证记录。

- 文件必须带 YAML front matter，并包含非空字符串 `author`、非空字符串数组 `references` 和 `expiration-time`。
- `expiration-time` 使用 `YYYYMMDD`；早于 CI 运行当天 UTC 日期的文档视为过期。`docs/tmp/example.md` 可以保留示例占位值，其他文件不得使用占位值。
- 校验实现是 `scripts/check-docs-tmp.mjs`，本地运行 `pnpm docs:check`。修改 schema 时必须同步更新示例、校验器和本规则，不能出现第二套约定。
- 临时文档不得成为长期设计或规则的唯一来源；方案确认后转写到 `roadmap`、`design` 或 `rules`，原文再删除或归档。
- 过期文档不得继续被当前文档链接；保留历史价值的内容只提炼成 `archive` 摘要。

## 归档

归档的目标是保留必要的历史上下文，而不是保留全部旧文档。归档摘要必须注明：原文主题、被什么当前文档取代、哪些内容不再适用。旧路径、旧 API 和旧迁移计划不得从归档页面伪装成当前建议。

## 提交前检查

文档变更至少执行：

```bash
git diff --check
pnpm fmt:check
```

并针对变更范围检查：

```bash
rg -n '旧路径|旧命令|旧接口名' README.md docs .github
```

如果修改了 `docs/tmp`，还必须通过该目录对应的 YAML/过期校验；如果修改了架构、路由、插件或开发命令，应同时核对对应源码与 workflow。
